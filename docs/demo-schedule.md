# Демонстрационное расписание

## Готовая демонстрация Docker

В Compose с `CINEMA_MODE=demo` расписание создаётся инициализатором и
проверяется фоновым процессом сайта: семь постоянных дат из
`data/demo-calendar.json` — 1–7 ноября 2025 года, московское время,
проверка пересечений и запас 30 минут между показами. Интервал по умолчанию
60 минут (`DEMO_SCHEDULE_REFRESH_MINUTES`). Существующие показы, билеты и
админские изменения сохраняются. Ручные скрипты для этого запуска не нужны.

Эта неделя — постоянный демонстрационный календарь, а не текущая афиша
реального кинотеатра. Даты доступны и до, и после ноября 2025 года.
Карточка фильма показывает даты, на которые у него есть сеансы.
API, выбор мест и покупка используют одну политику доступности. Указаны
год и пометка демонстрационного календаря; подписи «сегодня/завтра» в demo
не применяются. Купленные билеты остаются в личном кабинете.

В production разрешены только ещё не начавшиеся сеансы. Включить demo
через HTTP-параметр нельзя: режим задаётся серверной конфигурацией.

## Ручная загрузка при локальной разработке

После загрузки каталога выполните из корня проекта в PowerShell 7:

```powershell
./scripts/Update-DemoSchedule.ps1 -DemoCalendar
```

Флаг `-DemoCalendar` загружает семь дат из JSON. Его нельзя сочетать с
`StartDate` или `Days`. Профили Rider/http/https работают в режиме demo.
Для отдельной production-разработки без этого флага загрузка охватывает
сегодня и следующие 6 дней по Москве; можно задать `-StartDate yyyy-MM-dd`
и `-Days 1..14`. Этот вариант запрещает начало в прошлом.
В каждом из пяти залов запланированы показы в 10:00, 14:00, 18:00 и 22:00:
20 сеансов в день. Распределение фильмов по залам меняется.
Между фильмами учтён запас минимум 30 минут. Цены демонстрационные: 350–550 ₽.
Конфигурация залов описана в [демонстрационных залах](demo-halls.md).

Скрипт создаёт приватную резервную копию, выполняет загрузку транзакционно,
проверяет наличие фильмов и залов и отказывается от загрузки при пересечении
с другими сеансами. Повторный запуск на те же даты не создаёт дублей.
Распределение зависит от выбранной календарной даты. Существующие сеансы
и билеты сохраняются; изменение календаря не переносит проданные показы.

В production расписание не обновляется автоматически; используйте ручной
будущий календарь для разработки. В demo фоновый процесс заполняет отсутствующие
слоты фиксированной недели, но не восстанавливает намеренно удалённые
администратором показы со служебными ключами.

## Правила времени

Кинотеатр работает по Москве (`Europe/Moscow`, UTC+3). `Sessions.DateStart`
хранится в существующем `timestamp without time zone`: это местное время
кинотеатра, в .NET — `DateTimeKind.Unspecified`. Миграция для расписания не нужна.
Дата API имеет формат `ДД.ММ.ГГГГ` и означает московский календарный день.
Диапазон дня полуоткрытый: от полуночи включительно до следующей полуночи
исключительно. Скрытые фильмы исключены из публичной выдачи в любом режиме;
уже начавшиеся показы исключены в production. В demo разрешены только даты
постоянного календаря независимо от текущего времени.

API возвращает плоские DTO без EF-навигаций. `dateStart` передаётся без
смещения; интерфейс показывает время кинотеатра без перевода в часовой пояс
браузера. Для расчёта текущего времени используется `CinemaTime`, независимо
от часового пояса сервера. Эти правила относятся к сеансам; даты Identity
(например, окончание блокировки входа) сохраняют собственные правила UTC.

Нажатие на время сеанса открывает выбор мест. Для покупки нужен вход в учётную
запись. Покупка демонстрационная: деньги не списываются, билет доступен
для печати и в личном кабинете. Подробности: [покупка билетов](ticket-purchases.md).
