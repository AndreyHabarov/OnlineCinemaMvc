# Авторизация и защита запросов

Вход работает по email или российскому телефону. Передавайте один способ
входа, пароль и `rememberMe`. Email ищется средствами Identity с учётом
нормализации. Телефон приводится к `+7XXXXXXXXXX`; поддерживаются пробелы,
скобки, дефисы, национальный префикс 8 и запись из 10 цифр.
Если старые записи содержат один телефон у нескольких пользователей,
вход по телефону отклоняется; по email эти пользователи могут войти.
Регистрация проверяет занятость телефона. PostgreSQL вычисляет номер в
NormalizedPhoneNumber и защищает уникальным индексом. Из двух одновременных
регистраций одного номера одна завершается, другая получает HTTP 400.
Некорректные старые номера дают NULL и не мешают входу по email.
Миграция при дублирующихся корректных номерах отменяется целиком.
Конфликты нужно исправлять отдельно, сохраняя пользователей; перед миграцией
сделайте приватную резервную копию.

Для новых паролей требуется 8–128 символов, минимум одна латинская заглавная
и строчная буква и цифра. Ранее созданные пароли продолжают работать.
После 5 неудачных попыток Identity блокирует пользователя на 15 минут.
Неизвестный пользователь, неверный пароль и блокировка возвращают одинаковое
сообщение и HTTP 401. Неверная структура или валидация запроса — HTTP 400.
`rememberMe=false` создаёт сессионную cookie, `true` — постоянную.

Личный кабинет защищён `[Authorize]`. Гость перенаправляется на главную с
открытой формой входа; после входа выполняется переход в кабинет или на
локальную страницу, вызвавшую вход. Админка доступна только роли `admin`,
совпадающей с существующей ролью БД. Обычному пользователю возвращается 403.
AJAX-запросы с Accept: application/json получают 401 вместо страницы входа.

Для всех небезопасных MVC-методов включена проверка antiforgery. Общий шаблон
выдаёт токен; Axios передаёт его в `X-CSRF-TOKEN` только на текущий origin.
Обычные POST-формы используют токен Form Tag Helper. После входа страница
перезагружается, чтобы обновить токен и состояние пользователя.
При отсутствующем или неверном токене действие не выполняется и возвращается
HTTP 400 с русским сообщением. GET не должен изменять данные.

## Проверка

При работающем локальном сайте и PostgreSQL проекта, из корня в PowerShell 7:

```powershell
./scripts/Test-Authentication.ps1
```

Скрипт рассчитан на локальную БД текущего Docker Compose и сайт, подключённый
к этой же БД. Он создаёт временные учётные записи `codex-auth-…@example.invalid`,
проверяет регистрацию, ошибки валидации, оба способа входа, уникальность телефона в БД и параллельные регистрации, cookies, блокировку, CSRF, личный кабинет и роли. В конце удаляет
только собственные тестовые записи. Существующие пользователи не изменяются.
Проверочный пользователь получает роль администратора лишь на время проверки.
