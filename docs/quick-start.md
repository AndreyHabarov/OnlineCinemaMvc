# Запуск демонстрации OnlineCinema

Нужен Docker Desktop с Linux-контейнерами или Docker Engine с Docker Compose.
Устанавливать .NET, PostgreSQL, Rider и pgAdmin отдельно не требуется.
Первый запуск требует интернета для загрузки образов и зависимостей.

## Получение проекта

Скачайте ZIP с GitHub и распакуйте его или выполните:

```sh
git clone https://github.com/AndreyHabarov/OnlineCinemaMvc.git
cd OnlineCinemaMvc
```

Все следующие команды выполняются из папки с `docker-compose.yml`.

## Windows

Запустите Docker Desktop, затем в PowerShell:

```powershell
./scripts/Start-Demo.ps1
```

Скрипт создаст локальный `.env` со случайным паролем БД, соберёт приложение,
применит миграции, загрузит демоданные и дождётся готовности сайта.
Существующий `.env` сохраняется. Скрипт работает в PowerShell 5.1 и 7.

## Linux и macOS

```sh
cp .env.example .env
```

В `.env` замените `POSTGRES_PASSWORD` своим паролем. Сохраните файл, затем:

```sh
docker compose up --build -d --wait
```

## Проверка результата

Откройте [кинотеатр](http://localhost:8080). Если изменён `APP_PORT` в `.env`,
используйте выбранный порт. В каталоге — 36 американских фильмов 90-х на
трёх страницах, русские описания и локальные постеры. Есть пять залов,
506 мест, фотографии исполнителей, акции и три статьи о кино. Миграции и
сидирование выполняются автоматически. Постоянные демодаты — 1–7 ноября 2025;
они доступны независимо от сегодняшнего дня, фоновый процесс пополняет
незаполненные слоты, сохраняя покупки и пользовательские изменения.

1. Нажмите на постер и выберите демонстрационный сеанс через «Купить билет».
2. Зарегистрируйте тестовый аккаунт и войдите. После входа откроется выбор мест.
3. Выберите места, укажите возраст и подтвердите демонстрационную покупку.
4. Проверьте билет и историю в личном кабинете. Деньги не списываются.

Время сеансов — московское. Настоящие платёжные реквизиты не нужны.
Для админки можно заранее включить создание отдельного демоадминистратора
по [инструкции Docker](docker.md#демоданные). Демоадминистратор по умолчанию
не создаётся; существующие аккаунты автоматически не получают его роль.

## Остановка и повторный запуск

```sh
docker compose stop
docker compose up -d --wait
```

Пользователи, билеты, изображения акций и ключи cookies сохраняются в volumes.
Повторное сидирование не создаёт дубли и сохраняет админские изменения.
Не удаляйте volumes, если хотите сохранить данные.

## Если запуск не прошёл

- Проверьте, что Docker Desktop запущен и использует Linux-контейнеры.
- Если порт занят, измените `APP_PORT` или `POSTGRES_PORT` в `.env` и повторите
  запуск. По умолчанию сайт использует 8080, PostgreSQL — 5434.
- Проверьте `docker compose ps -a` и `docker compose logs initialize web db`.
  При ошибке миграций сайт ждёт успешного завершения инициализации.
- Изменение пароля в `.env` не меняет пароль уже созданной роли PostgreSQL.
  Используйте первоначальные настройки; не удаляйте БД для обхода этой ошибки.
- Не публикуйте `.env` и журналы с приватными настройками.
