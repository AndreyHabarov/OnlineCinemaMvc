# Локальный запуск OnlineCinema

Нужны .NET SDK 8 или новее, среда выполнения .NET 8 и запущенный Docker Desktop с Linux-контейнерами.

## Подготовка базы данных

В PowerShell из корня репозитория:

```powershell
./scripts/Initialize-Local.ps1
```

Скрипт создаёт `.env` со случайным паролем, запускает PostgreSQL 17 в Docker,
дожидается готовности базы и применяет существующие миграции EF Core.
Локальный `dotnet-ef` закреплён на версии 8.0.11, соответствующей EF Core проекта.
Повторный запуск сохраняет пароль и данные, а уже применённые миграции не выполняются повторно.

Подключение: `127.0.0.1:5434`, база `cinemadb`, пользователь `cinema`.
Пароль находится только в локальном `.env`.
Для другого порта измените `POSTGRES_PORT` в `.env` перед запуском скрипта.
Если существующий volume уже инициализирован, смена пароля в `.env` сама по себе
не меняет пароль пользователя PostgreSQL: его нужно менять отдельно в самой БД.

Скрипт записывает подключение в `OnlineCinema.Mvc/appsettings.Development.local.json`.
Этот файл загружается только в Development. Переменная окружения
`ConnectionStrings__Default` и аргументы командной строки имеют приоритет.
Для другой среды задавайте подключение через переменные окружения или хранилище секретов.
При отсутствии подключения приложение выдаёт понятную ошибку запуска.

`.env`, локальные настройки, `backlog.md`, `backups/` и старый `docker/db/`
исключены из Git. `.env.example` содержит только пример настроек.

## Запуск сайта

```powershell
dotnet run --project OnlineCinema.Mvc --launch-profile http
```

Адрес: `http://localhost:5175`.

Схема БД создаётся миграциями. Чтобы загрузить американские фильмы 90-х
с русскими описаниями и локальными постерами, выполните:

```powershell
./scripts/Update-DemoCatalog.ps1
./scripts/Update-DemoSeats.ps1
./scripts/Update-DemoSchedule.ps1
```

Подробности и источники: [Демонстрационный каталог](demo-catalog.md).
Миграции и загрузка каталога не создают демонстрационные учётные записи.

## Проверка и остановка

```powershell
docker compose ps
dotnet ef migrations list --project OnlineCinema.Domain --startup-project OnlineCinema.Mvc -- --environment Development
docker compose stop db
```

Данные хранятся в отдельном volume `onlinecinema_postgres_data` и сохраняются
после остановки или пересоздания контейнера. Команда `docker compose down -v`
удаляет volume вместе с данными; для обычной остановки используйте `stop`.

## Перенос существующей базы

Для текущей рабочей копии исходная `cinemadb` находилась в PostgreSQL Windows
на порту 5432. Перед переносом создан приватный дамп в `backups/`.
Контейнер использует отдельный порт 5434 и отдельное хранилище, поэтому исходная
БД и базы других проектов не затрагиваются.

Резервные копии могут содержать данные пользователей: храните их локально.
На новом компьютере загрузите каталог командой `./scripts/Update-DemoCatalog.ps1`.

Правила времени и загрузки расписания описаны в [инструкции](demo-schedule.md).
Схемы залов и сценарий демонстрационной покупки описаны в [инструкции покупки](ticket-purchases.md).
При запущенном сайте проверка API: `./scripts/Test-Sessions.ps1`.

## Изолированные ключи для проверочного запуска

Для отдельного проверочного процесса можно задать `--DataProtection:KeysPath <абсолютный путь к приватному каталогу>`. Например, использовать подпапку `backups/`. Каталог не включать в Git. На Windows ключи защищены DPAPI и привязаны к аккаунту процесса; на Linux файлы требуют защиты правами доступа и, для production, отдельного решения шифрования. Для постоянного развёртывания каталог должен сохраняться между перезапусками, иначе существующие cookie и токены станут недействительными. Без параметра используются стандартные настройки ASP.NET Core.
