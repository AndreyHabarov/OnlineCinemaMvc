# Docker: сайт и PostgreSQL

## Быстрый запуск

Нужен установленный и запущенный Docker Desktop/Engine с Docker Compose.
Скачайте ZIP репозитория или клонируйте его. .NET SDK, PostgreSQL и pgAdmin
на компьютере для демонстрации не нужны. Первый запуск скачивает образы
и NuGet-пакеты; требуется интернет.

В PowerShell из корня:

```powershell
./scripts/Start-Demo.ps1
```

Скрипт создаёт .env со случайным паролем, сохраняет уже существующий .env,
собирает контейнеры и ждёт готовности. Адрес по умолчанию http://localhost:8080.
Подготовить только настройки: `./scripts/Start-Demo.ps1 -PrepareOnly`.
Скрипт подготовки работает также в встроенном Windows PowerShell 5.1.

На Linux/macOS без PowerShell скопируйте `.env.example` в `.env`, задайте
свой пароль PostgreSQL и выполните:

```sh
docker compose up --build -d --wait
```

Порты меняются в .env: APP_PORT для сайта, POSTGRES_PORT для pgAdmin.
При занятом порте выберите свободный и повторите запуск. Пароль в .env
используется PostgreSQL только при создании пустого volume: его изменение
в файле не меняет пароль уже созданной роли. Сохраняйте существующий .env.

## Образ приложения

```powershell
docker build -t onlinecinema:local .
```

SDK находится только в стадии сборки. Финальный образ содержит runtime .NET,
скомпилированные Razor-страницы, локальные библиотеки и постеры, публичные JSON
демокаталога. Запускается от пользователя `app`, порт внутри контейнера — 8080.
Локальные подключения, `.env`, backlog, ключи, дампы и данные БД исключены
из контекста. Образ не содержит рабочие учётные записи или базу данных.

Место для загруженных акций и DataProtection-ключей подготовлено для отдельных
volumes. Ключи позволяют сохранять cookies между перезапусками; их тоже нужно
защищать и резервировать. PostgreSQL запускается отдельным сервисом.

В режиме demo первый запуск после миграций автоматически заполняет кинотеатр.

## Compose

Web подключается к db:5432 по внутренней сети. Порт сайта APP_PORT (8080),
порт PostgreSQL POSTGRES_PORT (5434) привязаны только к 127.0.0.1.
Сайт ждёт healthcheck БД и проверяет подключение на /health.
Volume postgres_data сохраняет БД, protection_keys — cookies,
promotion_uploads — загруженные изображения. Корень контейнера сайта read-only,
временные файлы находятся в tmpfs, Linux capabilities сброшены.

PostgreSQL можно оставить без внешнего порта:

    docker compose -f docker-compose.yml -f docker-compose.internal.yml up -d

Миграции автоматически выполняет initialize после готовности PostgreSQL. Web ждёт успешного завершения initialize; при отказе сайт не запускается. Повторный запуск применяет только новые миграции.

## Миграции

Инициализация выполняется отдельным CLI-процессом того же образа.
Session advisory lock PostgreSQL сериализует миграции EF Core 8, в том числе
при случайном запуске двух инициализаторов. Соединение остаётся открытым
до окончания; блокировка освобождается и при ошибке/завершении процесса.
Сайт сам миграции не применяет. Для обновления заранее сохраните БД.

Проверка на собственных пустых volumes:

    ./scripts/Test-ContainerMigrations.ps1

Она проверяет два параллельных процесса, повтор, readiness и запрет запуска
сайта после ошибки инициализации. Рабочий Compose-проект не удаляется.

## Демоданные

`CINEMA_MODE=demo` загружает 12 американских фильмов 90-х с русскими описаниями,
локальные постеры, жанры, пять залов и 506 мест, будущие сеансы на семь дней,
новости и информационную акцию. Залы используют локальные иллюстрации интерьеров;
демобаннер — собственный SVG проекта. Настоящей оплаты и скидок здесь нет.

Таблица DemoSeedRecords связывает стабильные ключи с ID. Существующие карточки
не перезаписываются; удалённые администратором записи не восстанавливаются.
Сидирование не удаляет пользователей, заказы и билеты. Слоты сеансов сохраняются,
прошедшие и пересекающиеся показы не создаются. Все операции — в транзакции.

Роль admin создаётся явно. Демоаккаунт по умолчанию выключен. Для его создания
задайте `DEMO_ADMIN_ENABLED=true`, `DEMO_ADMIN_EMAIL` и свой тестовый
`DEMO_ADMIN_PASSWORD` в локальном .env. Существующий аккаунт с таким email
не повышается в правах; выберите новый email. Повтор не меняет пароль/роль.
В `CINEMA_MODE=production` демоданные и демоаккаунт не загружаются.

Не удаляйте служебные ключи вручную: они хранят намерение сохранить изменения.
Для полностью чистой демонстрации используйте отдельный Compose-проект.

```powershell
./scripts/Test-ContainerDemo.ps1
```

Проверяет пустые volumes, картинки, все основные сценарии и повторный запуск
с реальным зарегистрированным пользователем и билетом, изменением карточки,
цены места и удалением новости. Удаляет только собственный проверочный проект.

## Актуальность расписания

В режиме demo сайт при старте и затем каждые `DEMO_SCHEDULE_REFRESH_MINUTES`
минут (по умолчанию 60) пополняет будущие слоты на семь календарных дней
по московскому времени. Интервал допустим от 1 до 1440 минут. Процесс создаёт
новый scope/DbContext и использует ту же транзакционную блокировку, что seed.
Несколько экземпляров сайта не создают дубли. Проданные/существующие показы,
цены и пользовательские изменения сохраняются; новые пересечения пропускаются.

При временном отказе БД ошибка журналируется без секретов, попытка повторяется
в следующий цикл. Production этот процесс не запускает. При остановке текущая
SQL-транзакция завершится или откатится; ожидающий таймер отменяется.

Проверка фонового обновления без перезапуска:

```powershell
./scripts/Test-ContainerDemo.ps1 -CheckScheduleRefresh
```

## Остановка, обновление и копии

Остановка с сохранением всех данных:

```sh
docker compose stop
```

Для согласованной копии БД и загруженных файлов остановите web, оставив db:

```powershell
docker compose stop web
./scripts/Backup-Docker.ps1
docker compose up -d --wait
```

Копия в игнорируемом backups содержит проверенный PostgreSQL custom dump,
архивы promotion_uploads и protection_keys. Ключи и дамп приватны: храните
их с ограниченным доступом и отдельно от Git/Docker-образа. На Linux каталогу
копии и созданному .env задаются права только владельца.

Обновление после резервной копии:

```sh
git pull --ff-only
docker compose up --build -d --wait
```

Миграции/seed выполняются перед сайтом; существующие данные сохраняются.
Восстановление сначала проверяйте в отдельном пустом Compose-проекте с другими
портами: запустите только db, скопируйте dump в контейнер и примените pg_restore
с `--no-owner --no-privileges --exit-on-error`. Верните архивы файлов в его
volumes, сохраняя пользователя app и права 700. Затем запустите initialize/web.

**Полный сброс демоданных удаляет БД, пользователей, билеты, загрузки и ключи:**

```sh
docker compose down --volumes
```

Следующий запуск создаст новую демонстрацию. Эта команда не выполняется
скриптами обычного запуска/обновления/резервного копирования.

## Production

Используйте отдельные БД/volumes и приватные пароли, `CINEMA_MODE=production`,
`DEMO_ADMIN_ENABLED=false`. Инициализатор блокирует БД с оставшимся
демоадминистратором: переключение режима само по себе не удаляет аккаунты.
Создание настоящего администратора требует отдельной согласованной процедуры.
Пароль демоадминистратора передаётся только initialize, а не web.

Текущий Compose публикует сайт только на локальном интерфейсе. Для публичного
сервера отдельно настраиваются HTTPS, доверенный reverse proxy, secrets,
пользователь БД с ограниченными правами и резервное копирование. Выбор сервера
и домена остаётся отдельной задачей; GitHub хранит код, а не запускает этот сайт.
