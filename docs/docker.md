# Docker: сайт и PostgreSQL

## Образ приложения

```powershell
docker build -t onlinecinema:local .
```

SDK находится только в стадии сборки. Финальный образ содержит runtime .NET,
скомпилированные Razor-страницы, локальные библиотеки и постеры, публичные JSON
демокаталога. Запускается от пользователя `app`, порт внутри контейнера — 8080.
Локальные подключения, `.env`, backlog, ключи, дампы и данные БД исключены
из контекста. Образ не содержит рабочие учётные записи или базу данных.

Место для загруженных акций и DataProtection-ключей подготовлено для отдельных
volumes. Ключи позволяют сохранять cookies между перезапусками; их тоже нужно
защищать и резервировать. PostgreSQL запускается отдельным сервисом.

Полная инструкция Compose добавляется после проверки миграций и сидирования.

## Compose

Web подключается к db:5432 по внутренней сети. Порт сайта APP_PORT (8080),
порт PostgreSQL POSTGRES_PORT (5434) привязаны только к 127.0.0.1.
Сайт ждёт healthcheck БД и проверяет подключение на /health.
Volume postgres_data сохраняет БД, protection_keys — cookies,
promotion_uploads — загруженные изображения. Корень контейнера сайта read-only,
временные файлы находятся в tmpfs, Linux capabilities сброшены.

PostgreSQL можно оставить без внешнего порта:

    docker compose -f docker-compose.yml -f docker-compose.internal.yml up -d

Миграции автоматически выполняет initialize после готовности PostgreSQL. Web ждёт успешного завершения initialize; при отказе сайт не запускается. Повторный запуск применяет только новые миграции.

## Миграции

Инициализация выполняется отдельным CLI-процессом того же образа.
Session advisory lock PostgreSQL сериализует миграции EF Core 8, в том числе
при случайном запуске двух инициализаторов. Соединение остаётся открытым
до окончания; блокировка освобождается и при ошибке/завершении процесса.
Сайт сам миграции не применяет. Для обновления заранее сохраните БД.

Проверка на собственных пустых volumes:

    ./scripts/Test-ContainerMigrations.ps1

Она проверяет два параллельных процесса, повтор, readiness и запрет запуска
сайта после ошибки инициализации. Рабочий Compose-проект не удаляется.
